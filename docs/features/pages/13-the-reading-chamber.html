The Reading Chamber

The PDF never reaches the browser. Pages are rendered once, watermarked on every request, and served as images.

ReadingD43D73D87built

Why it exists

The chamber is the thing the whole product exists to deliver, and it is built around one decision: the PDF never reaches the browser (D73). There is no PDF endpoint. Each page was rendered to an image when the chapter was uploaded, and every request for one burns the reader's name and a masked phone number into it.

A screenshot cannot be prevented by any web page. A watermark makes one traceable, which is what discourages passing a chapter around — and it is only possible because the server, not the browser, is what turns a page into pixels.

The design intent is inherited and still binding: Apple-clean, not fancy. No timers, no session metadata, no nudges. Chrome that fades away. Nothing moves while the reader is reading.

Rendered once, marked every time

What each part does

01
core/services/pages.py · render_and_save
Renders every page and records the layout — and returns False rather than raising when a PDF cannot be rendered, so one bad file does not fail an upload. The chamber has its own error for a chapter with no pages.
02
core/services/pages.py · _render
Rasterises with pypdfium2 at 1400px wide — sharp at two device pixels per CSS pixel on a ~700px column, and roughly 100–200KB per text page as WebP. Existing images at the same key are deleted first, so a re-render cannot leave a stale page behind.
03
core/services/pages.py · _sections
Flattens the PDF's bookmarks into title, zero-based page and depth, dropping anything that does not resolve to a page. No heading detection: a guessed table of contents is a wrong one.
04
core/services/pages.py · watermarked_page
Opens the stored image, composites the mark layer, re-encodes as WebP. The watermark is generated per request because it names the reader — the same page served to two readers is two different images.
05
core/services/pages.py · _diagonal_marks · _margin_line
The mark is drawn on a square big enough to cover the page at any rotation, rotated 30°, then cropped — which is how you get an evenly tiled diagonal without clipped text at the edges. Then one small centred line in the bottom margin, where a book keeps its small print.
06
core/services/pages.py · mark_for · mask_phone
Ada Demo · +91 ******3210 — enough to identify a leaked copy, not enough to publish someone's number. Asterisks rather than bullets, because Pillow's built-in font has no bullet glyph and a watermark of empty boxes names nobody.
07
core/api/grants.py · the two page endpoints
Both dispatch OPEN first, so access is re-checked on every page. The image response is inline, no-store and nosniff; a chapter that has not been rendered answers 404 and the chamber renders its own error.
08
components/PdfChamber/machine/
Two parallel regions: document (loading → rendered → error) and view (whether the reader has gone full screen). Independent, so going full screen while pages are still arriving is a valid state rather than a race.
09
components/PdfChamber/Pages.tsx · PageSkeletons.tsx
Each page's box is sized from the layout before its image arrives, so the column never reflows under the reader's eyes. Skeletons hold the space in the meantime.
10
components/PdfChamber/useIdle.ts · useFullscreenEvents.ts
Hooks that only measure: idleness fades the chrome away, and the fullscreen listener reports the browser's actual state. Neither decides anything — each hands its observation to the machine as an event.
11
pages/reader/Threshold.tsx
The ceremony on the first open of a link: four beats, each a state in the reader machine, so the sequence is data rather than a chain of timers. The chamber renders underneath from the first beat, so the pages load while it plays.

Gotchas

  • The chamber owns its own error. A grant can be perfect and the document still fail — a network blip, an unrendered chapter. Folding that into the page's error would tell a reader whose link is fine that their link is broken, and offer them sanctuary, which cannot help them.
  • A chapter with a null page_layout cannot be opened at all. That is why rendering also runs on every deploy: render_chapters sits in the start command and skips chapters that already have images, so a chapter uploaded before the feature existed becomes readable without anyone remembering to do it.
  • The layout must not carry image paths. It would hand the client a storage key, which is exactly what proxying the bytes exists to avoid.
  • Pages cannot be cached. They are per-reader documents behind a credential, so no-store — which also means a reader who scrolls back re-fetches, and the images have to stay small for that to feel free.
  • The watermark went through two designs. The first was legible enough to read through the text. D87 replaced it with marks at about 4% ink plus one margin line: still recoverable from a screenshot, no longer something the reader is reading around.
  • A rotated tile has to be drawn oversized and cropped. Rotating a page-sized layer leaves empty triangles in the corners, which is where a determined cropper would aim.
  • Rendering client-side was planned, then dropped. D71 had the chamber running pdf.js; D73 replaced it because the browser then holds the whole PDF, which is the thing that must not happen — and testing on real phones showed server-rendered pages were enough.
