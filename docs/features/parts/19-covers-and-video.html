Why it exists

Mandate 3 says never expose a storage URL: bytes are proxied through the API, which is what makes grant tokens and expiry meaningful and keeps the object store swappable. Video is the one exception in the whole product, and it is a deliberate one (D77).

The arithmetic is the argument. Streaming a video through Django holds a worker for as long as someone watches; on a free instance with two workers, a handful of viewers would starve every other request — including the request that serves a chapter. So a video plays from a short-lived signed URL instead. What the mandate protects still holds: nothing permanent is exposed, the bucket stays private, and one module knows how a URL is made.

Proxied, except for one thing

What each part does

01
core/services/media.py · signed_url
The only function that knows how a playable URL is made. With R2 it is a presigned GET expiring after VIDEO_URL_TTL_SECONDS; with local storage, which cannot sign, it is an absolute /media/ URL — the development fallback that keeps a fresh clone working.
02
core/services/media.py · chapter_video_url · sample_video_url
Two named wrappers, so the gating is visible at the call site: one is reached only through WATCH, the other is openly public.
03
core/services/media.py · cover_bytes
Reads the cover server-side and returns it with its content type. Covers stay proxied: they are small, and a cover is not worth a second exception.
04
core/machines/reading/ · the WATCH rows
Four rows, in this order: live and owned and has a video → sign it; past expiry → expired; owned but no video → no_video; anything else → not_owner. The video check sits after ownership on purpose, so a stranger learns nothing about which chapters have videos.
05
core/api/grants.py · GET /grants/{token}/video
Dispatches WATCH and returns whatever the action produced. The one place in the product where a storage URL reaches a client, and it is behind the same gate as the pages.
06
core/api/books.py · cover · sample
Both resolve the book through a helper that filters on is_published, so an unfinished book's media cannot be fetched by guessing its slug. The cover response carries an hour of public cache and nosniff.
07
core/models.py · the three video fields
Chapter.video (gated with its chapter), Book.sample_video (public), and Book.video (owners only, D83). All MP4-only with an env-driven size cap, and each on an upload path carrying a UUID.
08
pages/reader/ChapterVideo.tsx
A quiet link under the chapter title. The player opens only when asked and never starts on its own — nothing moves while the reader is reading — and the URL is held by the machine only while the player is open.
09
pages/reader/machine/ · the video region
A parallel region, so fetching a URL and opening the player never interrupts the pages: idle → fetching → playing, with failed beside them.
10
pages/admin/books/Cover.tsx · admin/book/Videos.tsx
The other end: a cover on each card in the admin list, and the panel that assigns dropped videos to chapters, the book or the sample slot.

Gotchas

  • A signed URL is a credential for as long as it lives, so it is never logged. That includes error paths: a log line with a playable URL outlives the request that made it.
  • The TTL is a trade, not a formality. Long enough that a reader can watch without the URL dying mid-play, short enough that a copied link is useless by the time it is shared. It is env-driven for exactly that reason.
  • Local storage cannot sign. Without the absolute-URL fallback, video would be the one feature that breaks on a fresh clone — which is the situation mandate 6 exists to prevent.
  • Ownership is checked before the video's existence. Reversing those two rows turns the endpoint into a probe for which chapters have videos.
  • Covers were nearly the second exception. They are on the same object store and the same argument applies in miniature — but they are small, they cache for an hour, and each re-upload gets a new name, so proxying costs nothing and keeps the rule intact.
  • Nothing transcodes. An MP4 is served exactly as uploaded, capped by size, so a badly-encoded file is a badly-playing video and the only fix is to upload a better one.
